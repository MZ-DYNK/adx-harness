전역 지식은 한 번 잘못 올리면 모든 프로젝트에 계속 영향을 줍니다. 게이트를
느슨하게 적용하지 마라.

1. `./harness promote` 를 실행한다. 후보가 없으면 그 사실만 알리고 끝낸다.

2. `올릴 수 있는 것` 각 항목을 사람이 판단할 수 있게 보여준다.
   - 무엇을 올리는지 한 줄
   - 어디로 가는지 (`PROFILE.md` / `DESIGN-TASTE.md` / 스킬 레퍼런스)
   - 왜 전역인지. 프로젝트 하나의 제약이 아니라는 근거
   - 올리면 앞으로 어떤 답이 달라지는지 구체적으로 한 줄

3. 아래에 해당하면 게이트를 통과했어도 **올리지 말자고 권한다.**
   - 한 프로젝트의 업무 성격에서 나온 것을 사람의 취향으로 일반화한 경우
   - 이미 스킬이나 정본에 같은 내용이 있는 경우
   - 문장이 너무 일반해서 앞으로 어떤 판단도 바꾸지 못하는 경우
   - 반대 사례를 한 번이라도 본 기억이 있는 경우

4. `아직 안 되는 것` 은 막힌 이유만 짧게 전한다. 우회 방법을 제안하지 마라.
   관찰 날짜나 프로젝트 이름을 고쳐서 통과시키는 것은 금지다.

5. 사용자가 승인한 항목만 목표 파일에 **한 줄씩** 추가한다.
   - 기존 문서 구조를 지키고 해당 절에만 넣는다
   - `확정된 선호` 와 `관찰 중인 선호` 를 구분한다
   - 문서를 다시 쓰지 마라
   - 추가한 뒤 후보의 `상태` 를 `승격` 으로 바꾼다

6. 기각한 항목은 상태를 `기각` 으로 바꾸고 이유를 한 줄 남긴다. 같은 후보가
   다시 올라오는 것을 막는다.

7. 끝나면 목표 파일의 줄 수와 상한을 알린다. 상한에 가까우면 무엇을 지울지
   먼저 제안한다.
