# 디자인 방향 렌즈

## 1. 제품과 행동

- 사용자가 반복해서 끝내야 하는 일은 무엇인가?
- 첫 5초 안에 무엇을 알아야 하는가?
- 가장 자주 보는 정보와 가장 위험한 행동은 무엇인가?
- 탐색, 비교, 생성, 모니터링, 구매, 협업 중 어떤 인터페이스인가?

운영 도구는 대체로 조용하고 조밀하며 스캔 가능해야 합니다. 런칭 페이지,
포트폴리오, 미디어 경험은 더 표현적일 수 있습니다.

## 2. 사용자와 환경

- 숙련도와 사용 빈도
- 모바일·데스크톱 비중
- 한 손 사용, 긴 세션, 야외, 저조도 등 환경
- 읽기 언어와 텍스트 길이
- 접근성 요구와 보조 기술

## 3. 시각적 방향

다음 축에서 의도적인 위치를 정합니다.

- dense ↔ spacious
- quiet ↔ expressive
- utilitarian ↔ editorial
- geometric ↔ organic
- neutral ↔ colorful
- static ↔ kinetic
- familiar ↔ novel

모든 축을 극단으로 만들지 않습니다. 제품의 핵심 행동을 돕는 한두 축에 집중합니다.

## 4. 구조

- 정보 우선순위와 읽기 순서
- 고정·유동 영역
- 탐색 깊이와 되돌아가기
- 비교를 위한 정렬과 그룹
- 빈 상태와 점진적 공개
- 모바일에서 사라지거나 재배치되는 요소

카드는 기본 컨테이너가 아닙니다. 섹션, 표, 리스트, 패널, 캔버스, 타임라인,
인라인 편집 중 내용 관계를 가장 잘 드러내는 구조를 선택합니다.

## 5. 시스템

- 기존 색상·타입·간격 토큰
- 현재 컴포넌트와 변형
- 아이콘 라이브러리
- 그림자, 테두리, 반경, 표면 규칙
- 모션 시간과 easing
- 데이터 시각화 규칙

새로운 토큰이나 의존성은 여러 화면에서 반복 가치가 있을 때만 추가합니다.

## 방향 카드

```md
### 방향 이름

- 시각적 명제:
- 가장 먼저 보이는 것:
- 레이아웃:
- 타이포와 밀도:
- 색과 표면:
- 인터랙션과 모션:
- 기억에 남을 요소:
- 장점:
- 대가:
- 가장 잘 맞는 상황:
```

## 검증

- 실제 콘텐츠의 짧고 긴 사례로 확인
- 모바일과 데스크톱 주요 폭 확인
- 키보드 이동과 focus 확인
- 대비와 reduced motion 확인
- 로딩·빈 상태·오류·권한 없음 확인
- 기존 시스템과의 시각적 drift 확인
