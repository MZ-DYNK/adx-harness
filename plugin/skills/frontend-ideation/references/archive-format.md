# 디자인·컴포넌트 아카이브 형식

## 레퍼런스 카드

```md
### 이름

- 출처:
- 확인일:
- 제품과 화면:
- 좋아한 이유:
- 가져올 패턴:
- 그대로 가져오면 안 되는 점:
- 적용 가능한 프로젝트:
- 상태: candidate | adopted | rejected
```

이미지나 URL만 저장하지 않습니다. 왜 유용한지와 적용 조건이 있어야 다시 쓸 수 있습니다.

## 화면 패턴 카드

```md
### 패턴 이름

- 해결하는 문제:
- 정보 구조:
- 적합한 밀도:
- 모바일 변화:
- 상호작용:
- 접근성:
- 피해야 할 상황:
- 사용한 프로젝트:
```

## 컴포넌트 카드

```md
### 컴포넌트 이름

- 목적:
- anatomy:
- variants:
- states:
- content constraints:
- responsive behavior:
- keyboard and focus:
- implementation notes:
- status: idea | prototype | production | retired
```

## 취향 신호

`확정`과 `관찰`을 분리합니다.

- 확정: 사용자가 직접 선호·비선호를 말했거나 선택 이유를 확인함
- 관찰: 한 프로젝트에서 선택했지만 제약 때문일 수 있음
- 승격: 여러 프로젝트에서 같은 이유로 반복되거나 사용자가 확인함

색상 하나나 특정 사이트를 좋아했다는 이유만으로 전체 스타일을 일반화하지 않습니다.

## 유지 규칙

- 중복 레퍼런스는 합칩니다.
- 오래된 링크에는 마지막 확인일을 남깁니다.
- 컴포넌트가 실제 코드에 존재하면 경로를 연결합니다.
- 거절된 아이디어도 이유가 재발 방지에 유용하면 남깁니다.
- 프로젝트 고유 제약은 전역 취향 파일로 옮기지 않습니다.
