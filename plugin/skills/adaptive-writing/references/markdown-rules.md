# Markdown 작성 규칙

## 기본 구조

- H1은 파일당 하나만 사용합니다.
- 제목 바로 아래에서 문서의 목적이나 결론을 짧게 밝힙니다.
- H2는 독립된 결정, 주제, 단계에만 사용합니다.
- 한 파일은 가능한 한 하나의 목적을 가집니다.
- 문서가 길어지면 주제별 파일로 분리하고 원본에는 짧은 색인을 둡니다.
- 상시 로드되는 규칙 문서는 120줄 안팎을 목표로 합니다. 상세 사례와
  도메인 지식은 `references/`로 옮깁니다.

## 문장과 목록

- 결론이나 결정부터 씁니다.
- 한 문단에는 하나의 주장만 둡니다.
- 병렬 정보는 목록으로, 정확한 필드 대응이나 비교만 표로 표현합니다.
- 목록의 각 항목은 같은 문법 형태로 시작합니다.
- 전문 용어는 필요할 때 첫 등장에만 `한국어(English)`로 병기합니다.
- 강조는 정말 구분이 필요한 단어에만 사용합니다. 문장 전체를 굵게 만들지 않습니다.
- 링크 텍스트는 목적지를 설명해야 합니다. `여기`나 원시 URL만 쓰지 않습니다.
- 날짜는 `YYYY-MM-DD`, 시간 기록은 현지 시간과 함께 일관되게 씁니다.

## 사실과 판단

- 외부 사실에는 출처를 붙입니다.
- 바뀔 수 있는 수치, 정책, 제품 기능에는 확인일을 적습니다.
- 추정치는 추정이라고 표시하고 계산 가정을 함께 둡니다.
- 사실, 해석, 추천을 같은 문장에 섞지 않습니다.
- 동일한 사실을 여러 파일에 복제하지 말고 기준 문서에 링크합니다.

## 수정 원칙

- 쓰기 전에 목적, 독자, 결과를 바꾸는 불확실성을 확인합니다.
- 요청에 필요한 만큼만 작성합니다. 미래를 위한 빈 섹션을 만들지 않습니다.
- 기존 파일을 수정할 때 주변 말투와 구조를 존중합니다.
- 관련 없는 문장, 포맷, 파일을 함께 정리하지 않습니다.
- 모든 중요한 문서 작업에는 확인 가능한 완료 기준을 둡니다.

이 규칙은 제3자 Karpathy-inspired 저장소의 네 행동 원칙을 문서 작업에
맞게 재해석한 것입니다. 원 저장소는 Markdown 규격 자체를 정의하지 않습니다.

## 피할 표현

- 의미 없는 서론: “오늘날 빠르게 변화하는 환경에서”
- 근거 없는 수식어: “혁신적인”, “획기적인”, “최고의”
- 내용 없는 메타 문장: “아래에서 자세히 알아보겠습니다”
- 같은 결론을 서론과 결론에서 반복
- 모든 내용을 카드, 표, 체크리스트로 바꾸는 과도한 형식화
- 사용자가 이미 아는 배경을 길게 되풀이하는 설명

## 자체 검토

- 첫 화면만 읽어도 결론과 다음 행동이 보이는가?
- 각 제목 아래에 실제로 독립된 내용이 있는가?
- 표가 목록보다 관계를 더 명확하게 만드는가?
- 삭제해도 의미가 변하지 않는 문장이 남아 있는가?
- 기존 문서를 건드린 모든 변경이 요청에 직접 연결되는가?
