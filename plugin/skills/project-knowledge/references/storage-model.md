# 프로젝트 지식 저장 모델

## 신뢰 단계

```text
원본 imports ─┐
일일 로그 ────┴→ 검토 → NOW / 프로젝트 기준 문서 / 전역 사용자 취향
     Markdown 정본 전체 ─→ 삭제 가능한 SQLite FTS 검색 인덱스
```

`imports`는 원문 근거 보관소이지 자동 문맥이나 프로젝트 진실이 아닙니다.
요약 인덱스로 먼저 범위를 좁히고 필요한 원본만 확인합니다.

### 검색 인덱스

- 역할: 질문과 관련된 정본·과거 기록·조사 요약의 위치를 빠르게 찾음
- 위치: `.harness/.index/knowledge.sqlite3`
- 신뢰: 원문이 아닌 삭제 가능한 파생 데이터
- 쓰기: 훅이 Markdown 변경을 감지해 전체 재생성
- 기본 범위: 프로젝트 정본, `wiki/**/*.md`, 전역 프로필과 디자인 취향
- 조건부 범위: 연속성 발화는 일일 로그, 출처를 명시한 발화는 imports의
  Markdown 조사 요약
- 제외: 첨부 원본, 바이너리, 긴 질문·답변 companion 파일
- 금지: DB를 직접 수정하거나 정본처럼 공유

### 일일 로그

- 역할: 실제 질문, 최종 답변, 주요 진행의 시간순 증거
- 신뢰: 관찰 기록이며 사실 보증이 아님
- 쓰기: 훅이 자동 append
- 읽기: 날짜나 키워드가 필요할 때만
- 공유: 기본 로컬

### 원본 imports

- 역할: 메일·채팅·첨부 원본과 재검증 가능한 조사 요약
- 신뢰: 1차 자료일 수 있지만 정의·기간·화자 맥락을 확인해야 함
- 읽기: 인덱스 → 관련 요약 → 필요한 원본 순서
- 공유: 기본 로컬, Git 및 자동 문맥 주입에서 제외
- 금지: 토큰, 쿠키, 비밀번호, 불필요한 개인정보

### NOW

- 역할: 현재 작업을 재개하기 위한 짧은 상태
- 신뢰: 진행 중인 가설과 상태를 포함
- 쓰기: 목표, 상태, blocker, next action이 바뀔 때
- 수명: 완료하거나 방향이 바뀌면 정리

### 프로젝트 기준 문서

- `PROJECT`: 안정적인 배경과 제약
- `WIKI`: 검증된 사실, 결정, 용어, 교훈
- `DESIGN`: 프로젝트 디자인 방향과 패턴
- `MARKETING`: 고객, 포지셔닝, CRM, 캠페인 학습
- 신뢰: 근거가 있거나 사용자가 수용한 내용
- 공유: 저장소 정책에 따라 버전 관리 가능

### 전역 프로필과 디자인 취향

- 역할: 프로젝트를 넘어 반복되는 사용자 선호
- 신뢰: 명시적 선호 또는 반복 확인된 관찰
- 주의: 프로젝트 제약을 개인 취향으로 오인하지 않음

## 분류 예시

| 정보 | 저장 위치 |
|---|---|
| 오늘 무엇을 물었고 무엇을 했는가 | 일일 로그 |
| 메일·Slack 첨부 원본과 출처별 조사 요약 | imports |
| 다음 턴에 이어갈 구현 단계 | NOW |
| 사용자가 승인한 가격 정책 | WIKI |
| 외부 기사에서 본 미확인 수치 | 로그 또는 MARKETING의 가설 |
| 검증된 고객 세그먼트 | MARKETING |
| 이번 프로젝트의 모바일 내비게이션 결정 | DESIGN |
| 여러 프로젝트에서 반복된 카드 비선호 | 전역 디자인 취향 |
| API 토큰 | 어디에도 저장하지 않음 |

## 승격 기준

다음 중 하나가 필요합니다.

- 사용자의 명시적 결정
- 코드, 데이터, 테스트, 계약, 공식 문서로 확인
- 여러 독립된 근거의 일치
- 반복 관찰 후 사용자 확인

승격할 때 원문 전체를 복사하지 말고 미래 작업에 필요한 결론, 근거, 날짜,
영향만 요약합니다.

조사 요약을 만들 때 서로 다른 관점을 한 항목으로 합치지 않습니다. 광고주,
인하우스, 대행사, 고객의 발화는 각각 화자와 출처를 붙여 분리해 둡니다. 상류
요약에서 관점을 합치면 이후 결정 단계에서 다시 분리할 수 없습니다.

## 분리 기준

처음에는 단일 파일을 유지합니다. 다음 조건에서만 주제별 파일로 분리합니다.

- 500줄을 넘어 탐색이 느려짐
- 독립된 주제가 반복적으로 따로 참조됨
- 서로 다른 담당자나 변경 주기를 가짐

분리 후에도 원래 파일은 짧은 색인과 기준 위치를 알려야 합니다.
