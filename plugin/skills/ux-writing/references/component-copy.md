# 컴포넌트별 문구 패턴

각 컴포넌트는 사용자가 문구를 읽는 시간과 할 수 있는 행동이 다릅니다. 같은
내용도 자리마다 다르게 씁니다.

## 버튼과 CTA

- 사용자가 하는 행동을 짧게 씁니다. `저장`, `삭제`, `보내기`, `결제하기`
- `-하기` 명사화를 습관처럼 붙이지 않습니다. `삭제하기`보다 `삭제`가 짧고
  분명합니다. 다만 `결제하기`처럼 관용이 굳은 것은 그대로 씁니다
- `확인`은 무엇을 하는지 알려주지 않습니다. 실제 동작을 씁니다
- `네 / 아니오`를 쓰지 않습니다. 다이얼로그 본문의 동사와 같은 말을 씁니다
- 2~6자를 기준으로 하고, 넘으면 문구가 아니라 구조를 의심합니다

| 상황 | 나쁜 예 | 고친 예 |
|---|---|---|
| 삭제 확인 | 확인 | 삭제 |
| 양식 제출 | 제출하기를 클릭 | 제출 |
| 결제 진행 | 다음 단계로 이동하기 | 결제하기 |
| 취소 | 아니오 | 취소 |

## 에러와 검증 메시지

토스가 공개한 에러 메시지 원칙과 같은 방향입니다. **무엇이 문제인지 + 어떻게
고치는지**를 함께 줍니다. 실패 사실만 알리면 사용자가 갇힙니다.

- 시스템 상태를 서술합니다. 사용자를 탓하지 않습니다
- 복구 방법을 문구에 넣거나 버튼으로 연결합니다
- 개발자 용어를 노출하지 않습니다. `4xx`, `timeout`, `null`, `parse error`
- 부정형보다 가능형을 씁니다
- 필드 검증은 조건을 구체적으로 씁니다

| 나쁜 예 | 고친 예 |
|---|---|
| 오류가 발생했습니다 | 카드 승인이 거절됐어요. 다른 카드로 결제해 주세요 |
| 잘못 입력하셨습니다 | 이메일에 @가 없어요 |
| 비밀번호가 유효하지 않습니다 | 비밀번호는 8자 이상이어야 해요 |
| 네트워크 오류 (ERR_TIMEOUT) | 연결이 끊겼어요. 다시 시도해 주세요 |

## 토스트와 스낵바

3~5초 뒤에 사라집니다. 읽을 시간이 그만큼입니다.

- 한 문장, 한 정보만 담습니다
- 사용자가 놓치면 안 되는 내용은 토스트에 두지 않습니다. 다이얼로그나 인라인
  메시지를 씁니다
- 되돌릴 수 있으면 `되돌리기` 액션을 함께 둡니다
- `성공적으로 완료되었습니다` 대신 무엇이 끝났는지 씁니다

| 나쁜 예 | 고친 예 |
|---|---|
| 성공적으로 저장되었습니다 | 저장했어요 |
| 3개 항목이 성공적으로 삭제 처리되었습니다 | 3개 삭제했어요 · 되돌리기 |

## 빈 상태

빈 화면은 실수가 아니라 첫 화면인 경우가 많습니다. 상태 설명과 다음 행동을
함께 줍니다.

- `데이터가 없습니다`로 끝내지 않습니다
- 처음 쓰는 사람인지, 검색 결과가 없는 것인지, 다 처리해서 비었는지 구분합니다
- 다음 행동 버튼을 하나만 둡니다

| 상황 | 문구 | 액션 |
|---|---|---|
| 최초 진입 | 아직 등록한 캠페인이 없어요 | 캠페인 만들기 |
| 검색 결과 없음 | `광고비`로 찾은 결과가 없어요. 다른 말로 찾아보세요 | 검색어 지우기 |
| 모두 처리함 | 확인할 알림을 다 봤어요 | (없음) |
| 권한 없음 | 이 목록은 관리자만 볼 수 있어요 | 권한 요청 |

## 확인 다이얼로그

- 제목에 무엇을 하는지 씁니다. 본문에 되돌릴 수 있는지와 영향 범위를 씁니다
- 버튼 라벨을 본문의 동사와 일치시킵니다
- 파괴적 동작은 결과를 구체적으로 알립니다
- 버튼 배치는 제품 전체에서 한 방향으로 고정합니다

```text
제목    소재 3개를 삭제할까요?
본문    삭제하면 성과 기록도 함께 사라지고 되돌릴 수 없어요.
버튼    [취소]  [삭제]
```

## 폼 라벨, 헬퍼, 플레이스홀더

- 라벨은 항상 보이게 둡니다. 플레이스홀더로 라벨을 대신하지 않습니다
- 플레이스홀더는 예시를 넣습니다. `이메일 입력` 대신 `name@company.com`
- 필수 조건은 입력 전에 헬퍼로 알려 주고, 검증 실패 뒤에 처음 알리지 않습니다
- 왜 필요한지 설명이 필요한 항목은 헬퍼에 한 줄로 씁니다

| 요소 | 나쁜 예 | 고친 예 |
|---|---|---|
| 라벨 | 이메일을 입력해 주세요 | 이메일 |
| 플레이스홀더 | 이메일 입력 | name@company.com |
| 헬퍼 | (없음) | 로그인과 알림에 사용해요 |
| 에러 | 형식 오류 | @를 포함한 주소를 입력해 주세요 |

## 로딩과 진행

- `잠시만 기다려 주세요`를 쓰지 않습니다. 무엇을 하는 중인지 씁니다
- 3초 넘게 걸리면 진행 상태나 남은 단계를 알립니다
- 낙관적 UI를 쓸 때는 실패 시 되돌아가는 문구를 미리 준비합니다

| 나쁜 예 | 고친 예 |
|---|---|
| 로딩 중... 잠시만 기다려 주세요 | 리포트를 불러오는 중 |
| 처리 중 | 3개 중 2개 업로드했어요 |

## 권한과 동의

- 왜 필요한지 먼저 말하고 나서 요청합니다
- 거부해도 쓸 수 있는 범위를 알려 줍니다
- 마케팅 수신 동의는 정보성과 광고성을 구분해 표기합니다. 문구에 혜택을 넣으면
  광고성으로 바뀌므로 동의 요건이 달라집니다

## 길이와 문장

- 한 문장은 20단어 안쪽으로 씁니다. 넘으면 나눕니다
- 일반 사용자가 모를 외래어는 우리말로 바꿉니다
- 화면 폭이 좁은 자리는 글자 수 상한을 문구와 함께 적어 둡니다
